Fetch Succeeded, Parse Failed

Published MCP client identities (CIMD) against Keycloak: which are accepted, why the rest are refused, where an extension can act, and what a narrow change costs in validation coverage. Ten checks you can run on your own machine.

What was measured

Eight CIMD documents published by their vendors, fetched live and sent to Keycloak by the lab itself (not by the client programs), against Keycloak 26.7.0 and 26.8.0 (26.8.1 measured separately, same results).   • The fetch succeeded; the parse failed. The caller sees Client Metadata fetch failed; the server log for the same request names the unrecognized property. RFC 7591 §2, which the CIMD draft builds on, says an authorization server MUST ignore client metadata it does not understand.
  • Cause, both directions: adding token_endpoint_auth_methods_supported to an accepted document makes it fail; removing it from a refused one makes it pass.
  • Where an extension can act: a CIMD provider's createClientMetadata, its only method that receives the document, is never called when the parse fails. The executor's fetch-and-parse is where the document is.
  • One fetch-and-parse override (one Jackson flag): all eight accepted and persisted in one run, with anonymous registration refused in the same realm; five negative controls stay refused, each for its own reason.

Not claimed

  • Not a discovery. The parse defect is reported upstream: keycloak#51039, #51236 and the open PR #51235, and #53363 for the registration endpoint. This work adds the measured matrix, the single-variable cause, the extension point and a bounded regression set.
  • Not a fix. lenient-cimd is an experiment on an internal SPI, to be removed when upstream resolves the issue. Its negative controls are bounded coverage, not proof that nothing else changed.
  • Eight documents are not an ecosystem ratio. The checks stop at the login page; token issuance was measured in a separate run with real agent clients (real-clients/): Copilot CLI and Hermes get tokens on stock Keycloak, Codex CLI and goose only with the extension.

Run it

git clone https://github.com/graphsentinel/cimd-fetch-parse.git && cd cimd-fetch-parse
scripts/platform.sh install   # only what is missing: podman, jq, curl, python3, openssl, iproute2
scripts/lab.sh all            # build, start the lab, run every check 3x on 26.7.0 and 26.8.0
scripts/lab.sh uninstall      # removes only this lab's containers and processes

Reference runs: clean Ubuntu 26.04 VM, 100/100 checks PASS over five rounds; clean Ubuntu 24.04 VM, 20/20; each followed by a reinstall round (20/20) and an uninstall. Raw requests, server logs and summaries are in evidence/.
